## 結論

**この端末はマルウェアに感染しています。** しかも後から感染したのではなく、**工場出荷時のファームウェアに最初から仕込まれています。**

中核は `libandroid_runtime.so`（Zygote が読み込む Android の中核ネイティブライブラリ）に埋め込まれた**多段バックドア**で、**端末上で動作する全アプリのプロセス内で実行**されます。アプリではないため、アプリ一覧にも設定画面にも現れず、アンインストールもファクトリーリセットもできません。

さらに、指紋認証アプリによる**顔写真の平文アップロード**、OEM製アップデータによる**任意APKのサイレントインストール機能**、任意アプリから**IMEI/シリアルを書き換えられる脆弱性**が併存します。

## 1. 【最重要】libandroid_runtime.so に仕込まれた多段バックドア

### 1.1 第1段: ネイティブライブラリへの DEX 埋め込み

| 項目 | 内容 |
|---|---|
| 対象ファイル | `/system/lib64/libandroid_runtime.so`（2,235,928 B）<br>`/system/lib/libandroid_runtime.so`（1,597,556 B） |
| 埋め込み位置 | `.rodata` セクション内（lib64: オフセット `0x89e00`） |
| 埋め込み物 | JAR 60,753 B / SHA-256 `5bb7708755530d86435d6e8718d801ec184e9af31cba9682428a90aed43d3ae6` |
| 内容 | `META-INF/MANIFEST.MF`（`Created-By: dx 1.16`）+ `classes.dex` 85,472 B |
| JAR内タイムスタンプ | **2024-12-23**（ファームウェアのビルド日 2026-07-08 と乖離＝別途作成された成果物の後付け） |

**AOSP の `libandroid_runtime.so` に DEX/JAR が埋め込まれることは一切ありません。**
32bit版と64bit版という**アーキテクチャの異なる2つのバイナリに、バイト単位で完全に同一のペイロード**が入っている点が、コンパイラ由来ではなく**自動化されたビルド後パッチ**であることを示しています。

**感染範囲の限定確認:** system/vendor/product 配下の ELF オブジェクト 2,409 個を全走査した結果、ペイロードを含むのはこの2ファイルのみでした（`libziparchive.so` の検出は ZIP パーサ自身が持つマジックバイト定数による誤検知）。

- 改竄された `libandroid_runtime.so` は、**メーカーが署名し dm-verity で保護している正規のシステムイメージそのものに含まれる**

## 5. 【中】Verified Boot が暗号学的に無意味

ルート `vbmeta` の署名検証を AOSP 公開テスト鍵で実行した結果:
```
$ avbtool verify_image --image vbmeta_a.img --key external/avb/test/data/testkey_rsa2048.pem
vbmeta: Successfully verified SHA256_RSA2048 vbmeta struct in vbmeta_a.img
```

**この端末の Verified Boot のルート鍵は、AOSP のソースツリーで誰でも入手できる公開テスト鍵です。** この鍵の modulus は `lk_a.img` のオフセット `0xb6274` にも埋め込まれており、ブートローダの信頼の起点そのものがテスト鍵であることが確認できます。

加えて、ダンプメタデータの `target_config` は `sbc: false`（SoCのセキュアブートfuse未書き込み）を示しており、BootROM が preloader を検証していません。

結果として、**preloader → LK → AVB のチェーン全体にハードウェア上の信頼の起点が存在しません。** USBケーブルと短時間の物理アクセスがあれば、誰でも「緑（green）」状態を保ったまま永続的なバックドアを追加できます。

## 8. 推奨対応

### 8.1 端末について

**この端末の使用停止を強く推奨します。**

- **駆除は不可能です。** インプラントはアプリではなく、dm-verity で保護されたシステムイメージ内のネイティブライブラリに存在します。ファクトリーリセットでも、アプリのアンインストールでも、セキュリティアプリでも除去できません。
- **同じファームウェアでの再フラッシュも無意味です。** インプラントは署名済みイメージそのものに含まれています。
- 代替ファームウェアの導入は、ブートローダの信頼の起点がテスト鍵である以上、そもそも検証を信頼できません。

### 8.2 この端末で使用した情報について

インプラントは WhatsApp / Instagram / X / Chrome / Google Play / 設定アプリのプロセス内で動作していました。以下を前提に対応してください。

1. この端末でログインしたすべてのアカウントの**パスワードを別の安全な端末から変更**する
2. 同じく**二要素認証を再設定**する（SMSベースの2FAは `SmsManager` へのアクセスがあるため特に危険）
3. この端末で入力したクレジットカード情報があれば、カード会社に連絡する
4. この端末で顔認証を登録していた場合、その顔写真は `face.heils.cn` に平文HTTPで送信済みと考える
5. この端末に保存していた連絡先・写真・メッセージは漏洩したものとして扱う

### 8.3 さらに確証を得たい場合（任意）

- **実機での動的解析:** AiotFota の Legu パックを Frida / frida-dexdump で解除し、実際の通信先と Redstone SDK の有無を確定する
- **通信の傍受:** mitmproxy で起動時のチェックイン通信を取得（インプラントは TLS 検証を無効化しているため、証明書ピンニング回避すら不要）
- **設定ファイルの回収:** 起動済み端末から `/data/local/tmp/.SystemConfig` または `/sdcard/.SystemConfig` を取得し、AES鍵 `M9FNY5PNCx2ZwJam` で復号すれば現在のC2ドメインリストが判明する
- **通報:** 復元済みのペイロード（下記IOC）を Google Play Protect / セキュリティベンダに提供する
