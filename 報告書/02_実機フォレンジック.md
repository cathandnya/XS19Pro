# XS19Pro 実機フォレンジック 追補報告

**調査日:** 2026-07-31
**方法:** ADB(非root、shell権限)による稼働中実機の生体調査
**端末:** XS19Pro / シリアル `XS19PRO＜シリアル秘匿＞` / 機内モード維持
**前提:** [XS19Pro_マルウェア調査報告.md](XS19Pro_マルウェア調査報告.md) の静的解析結果

---

## 要旨

ファームウェアダンプの静的解析で復元したインプラントが、**実機で現に稼働していること**を確定した。さらに静的解析では到達できなかった**第4段ペイロードの存在と実行**を、PackageManager の dex 使用記録から証明した。第4段はファームウェアに含まれておらず、**C2から配信されたコード**である。

## 2. 復元コードと実機挙動の暗号学的一致

復元した第2段(`com.system.framework.media.a.f`)は、プロセス間通知に使うブロードキャスト名を次の式で生成する。

```java
c.A + i.a(Build.MODEL.replaceAll(" ","_") + Build.BRAND.replaceAll(" ","_"))
// c.A = "android.intent.action.SYSTEM_MEDIA_" , i.a() = MD5→大文字HEX
```

実機の `Build.MODEL` = `XS19Pro`、`Build.BRAND` = `XS19Pro`。

```
計算値: android.intent.action.SYSTEM_MEDIA_2B1D273614049D05354E6C32FFB9CA44
実機値: android.intent.action.SYSTEM_MEDIA_2B1D273614049D05354E6C32FFB9CA44   → 一致
```

プロセス個別チャネルも同コードの `getPackageName() + "." + MD5 + "_" + currentTimeMillis()` 形式で実測された。

```
com.android.providers.calendar.2B1D273614049D05354E6C32FFB9CA44_1785456226761
com.google.android.apps.restore.2B1D273614049D05354E6C32FFB9CA44_1785455911758
com.mediatek.ims.2B1D273614049D05354E6C32FFB9CA44_1785305103935
```

**復元コードが実行中のコードと同一であることの、事実上の証明である。**

## 5. 【新発見】第4段ペイロードの存在と実行

PackageManager は `DexClassLoader` 経由の読み込みを dexopt 用に記録する(`/data/system/package-dex-usage.list`)。**ペイロード本体が削除された後もこの記録は残る。**

### 5.1 完全なクラスローダ連鎖

```
PCL[ /data/data/<pkg>/ext_oat/com@system@framework@media@v2306.jar ]      ← 第2段(ネイティブが展開)
  └ PCL[ /data/user/0/<pkg>/files/.<name>/<name>@<uid>.jar ]              ← 第3段(第2段がBase64展開)
      └ PCL[ /data/user/0/<pkg>/.cofigs/.google_service_config.jar ]      ← 第4段(★ファームウェアに存在しない)
```

実測値:
```
/data/data/com.android.vending/ext_oat/com@system@framework@media@v2306.jar
/data/user/0/com.android.vending/files/.vending/vending@10099.jar
/data/user/0/com.android.vending/.cofigs/.google_service_config.jar

/data/data/com.android.chrome/ext_oat/com@system@framework@media@v2306.jar
/data/user/0/com.android.chrome/files/.chrome/chrome@10111.jar
/data/user/0/com.android.chrome/.cofigs/.google_service_config.jar

/data/data/com.android.launcher3/ext_oat/com@system@framework@media@v2306.jar
/data/user/0/com.android.launcher3/files/.launcher3/launcher3@10119.jar
```

第3段のファイル名 `<name>@<uid>.jar` は復元コード `d.java` の生成規則と完全に一致する。

```java

fileName = tempName + "@" + Process.myUid();    // → vending@10099
```

### 5.2 第4段は実行された

```

```

ART が `.vdex` を生成している。**ダウンロードされただけでなく、実際に読み込まれ実行された証拠。**

## 6. 追加コードの配信は確認、ただし内容は未取得

第4段 `.google_service_config.jar` は**ファームウェアのどこにも存在しない**。ELFオブジェクト2,409個の全走査で埋め込みペイロードは `libandroid_runtime.so` 2ファイルのみであり、そこに含まれる第3段2本(`extplog` / `systemupdate`)のいずれも `google_service_config` という名前ではない。

したがって第4段は**C2から配信されたコード**である。C2ドメイン `w5ybj0.s6jvxl.com` が停止措置(clientHold)を受けたのは 2026-07-29 21:16 JST、端末のセットアップは 2026-07-28 19:17 JST。**約26時間の配信可能窓が存在した。**

傍証として、通常ほぼ外向き通信を行わない `com.android.launcher3`(UID 10119)に、この窓の内側にあたる 2026-07-29 19:00〜21:00 JST のバケットで送信 4,750 バイト / 29 パケットが記録されている。ただし2時間幅のバケットであり、単独では決定的でない。

## 7. 汚染されていないことを確認した項目

- **追加アプリのインストールなし。** サードパーティは5本のみ、すべて `installer=com.android.vending`(いずれも Google / Microsoft の正規アプリ。個別名は秘匿)。アンインストール済みを含めても同一。
- **`/sdcard` に投下物なし。** 隠しファイルは0件。`.SystemConfig`、`.SystemData`、`.google_service_config`、`.cofigs` はいずれも不在。
- **`/data/local/tmp` に投下物なし。** 開発ツールが作成したディレクトリ1件のみ。

インプラントは投下先として `/data/local/tmp` と `/sdcard` を持つが、**実際にはアプリ非公開領域のみを使用している**(より隠密で、非root権限では読めない)。

## 8. 第4段の抽出可否 — 全経路を検証済み

| 経路 | 結果 | 根拠 |
|---|---|---|
| ADB shell 直接読み取り | **不可** | `Permission denied`(`/data/data/<pkg>` は 0700、アプリ所有) |
| `adb backup` | **不可** | launcher3 は `<include>` のみの `backupscheme.xml`(`launcher.db` / prefs / json の3件限定)。vending は `VendingBackupAgent`、chrome は `ChromeBackupAgent` の key/value バックアップで `fullBackupOnly=false`。packageinstaller は `allowBackup=false` |
| mtkclient で userdata 生ダンプ | **不可** | FBE。`fileencryption=aes-256-xts:aes-256-cts:v2` + `keydirectory=/metadata/vold/metadata_encryption`。ファイル名・内容とも暗号化、鍵は TEE 内 |
| ブートローダアンロックで root 取得 | **不可(逆効果)** | アンロックは `/data` を消去する。取得対象そのものが失われる |
| `/data/system/package-dex-usage.list` 直接読み取り | **不可** | `-rw------- system system` |

**結論: 非破壊で第4段を取得する経路は存在しない。**

## 9. 残る調査手段

### 9.1 制御ネットワークでの通信捕捉(実施可能・最有力)

インプラントは TLS 検証を完全に無効化している(`checkServerTrusted` 空実装、`HostnameVerifier` 常時 true)ため、**自己署名証明書で容易に傍受できる**。

手順: 隔離Wi-Fi(インターネット経路なし) → DNS で `w5ybj0.s6jvxl.com` を検査機に解決 → ポート10129で HTTPS 待受 → チェックイン受信。

得られるもの: 実際に送信される端末フィンガープリント JSON の全内容。復号鍵は取得済み(`wKLTStIx6WpciL5x` / `i9ZF2o6We7v3126f`、RSA鍵ペア)。

留意点: 送信間隔はサーバ応答の `nextRequestTime` に依存し、コード中には3日(259,200,000 ms)のゲートも存在するため、即座に発報するとは限らない。

### 9.2 公開脅威情報との照合(実施中)

C2ドメイン、6件のハッシュ、特異な文字列(`com@system@framework@media@v2306.jar`、`.cofigs`、`com.system.framework.media`、`statlib.STMM` 等)を公開情報と突合し、既知キャンペーンとの一致および第4段の公開検体の有無を調査中。

### 9.3 実施しない/推奨しない

- **ブートローダアンロック** — 証拠を消去する
- **端末をインターネットに再接続** — 実害の可能性があり、得るものがない

## 12. 調査上の留意事項

- 実機調査の過程で `logcat -c` を1度実行しログバッファをクリアした。クリア前の内容は本報告に採録済みだが、それ以前の履歴の一部は失われた。
- 端末は調査中も稼働を継続しており、新規プロセスへの展開が進行している。証拠状態を固定したい場合は電源を切る必要がある。
- 本調査は非root・読み取り専用で実施し、端末の設定変更・ファイル書き込みは行っていない(bugreport生成を除く)。
