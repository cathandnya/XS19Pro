# XS19Pro インプラント 帰属分析報告

**調査日:** 2026-07-31
**位置づけ:** [静的解析報告](XS19Pro_マルウェア調査報告.md) および [実機フォレンジック追補](XS19Pro_実機フォレンジック追補.md) の続報

---

## 要旨

本インプラントは **Triada の `libandroid_runtime.so` 系統**(Dr.Web 命名 `Android.Triada.231` の系譜)である。

決定打は、**まったく別のメーカー・別の国の端末**(ロシア市場向け INOI A75 Elegance / MediaTek MT6789 / Android 14)から採取された公開検体との**バイト単位の完全一致**である。同一のマルウェアが、少なくとも2つの無関係な ODM のファームウェアに混入していることが実証された。

さらに、非破壊では取得不可能と結論した**第4段ペイロードの中身が、この公開解析によって判明した**。

一方で、**商用のセキュリティベンダ・サンドボックス・脅威情報集約サービスのいずれも、本件の指標を公開していない**。検出情報は事実上存在しない。

## 3. ファミリー判定

### 該当: Triada — `Android.Triada.231` 系統

Dr.Web の [Android.Triada.231](https://vms.drweb.com/virus/?i=15508575) は次を記述する。

- `libandroid_runtime.so` に埋め込まれ、`println_native`(`android.util.Log`)をフックする
- 改変ライブラリから JAR モジュールを取り出し、アプリプロセスへ注入する
- **`os.config.ppgl.status`** 等のプロパティを設定する
- 2017年以降、40機種以上の低価格 Android 端末で確認

本調査の検体には `os.config.ppgl.status` が**そのまま存在する**。また `com.android.mms`(Triada.231 本来の注入対象)の文字列も含まれる。

**独立した裏付け:** McAfee の 2026年3月「Operation NoVoice」研究は、`os.config.ppgl.status` の共有と `libandroid_runtime.so` 置換手法を根拠に Triada との関連を明示し、`Android.Triada.231` を名指ししている([McAfee](https://www.mcafee.com/blogs/other-blogs/mcafee-labs/new-research-operation-novoice-rootkit-malware-android/))。

**注目すべき事実:** Google の GMS バイナリはこのプロパティ名前空間をハードコードしている。逆コンパイルされた `com.google.android.gms` のクラス `aqfa` に以下がある。

```java
public static final String[] f85934a = {"os.config.ppgl.dir", "os.config.ppgl.version",
                                        "os.config.ppgl.status", "os.config.ppgl.cd"};
```

周辺コードは SafetyNet / Verify Apps のテレメトリである。**Google は2020年頃からこのプロパティを有害アプリ指標として収集している**([gms_decompiled](https://github.com/Romern/gms_decompiled/blob/master/sources/p000/aqfa.java))。

### 非該当と判定した候補

| 候補 | 判定 | 根拠 |
|---|---|---|
| Kaspersky Triada.z(2025, 模造端末) | **非該当** | 感染経路が `/system/framework/arm[64]/binder.so` + `boot-framework.oat`、モジュールは `mms-core.jar`。C2 は `lnwxfq.qz94.com` 等で本件と重複なし。同じ系統樹の別枝 |
| BadBox / BadBox 2.0 | **手法同一・実装別** | `libandroid_runtime.so` 改変かつ「Triada ベース」だが、ローダは `com.hs.app` + `libanl.so`。本件は `com.system.framework.media.services`。C2・ハッシュの重複なし |
| Guerrilla / Lemon Group | **手法が最も近い** | `println_native` フック + データセクションからの DEX 復号という点で構造的に同一。ただし IOC の重複なし |
| Keenadu(Kaspersky, 2026年2月) | **非該当** | `libandroid_runtime.so` + Zygote + MediaTek + ファームウェア段階混入と条件は似るが、RC4(XORでない)、`com.ak.test.Main`、C2 は `keepgo123.com` 等。**IOC の重複ゼロ** |
| Vo1d | **非該当** | `/system/bin/debuggerd` 置換 + ネイティブ ELF。DEX-in-.so ではない |
| Necro / Fleckpe | **非該当** | いずれも Google Play 経由。ファームウェア常駐部分を持たない |
| Andr/Xgen2-CY | **判定不能** | Sophos のヒューリスティック総称。帰属価値なし |

**結論:** 本件は Triada 派生のファームウェアサプライチェーン型クラスタ(Triada.231 → Guerrilla → BadBox → Keenadu)に属する、**公開名を持たない独自の変種**である。Kaspersky は Keenadu 報告でこれらのボットネット群の相互関連を明示している。

## 4. 【解決】第4段ペイロードの正体

非破壊での取得は不可能と結論していたが、公開解析により内容が判明した。

| 項目 | 内容 |
|---|---|
| ファイル | `.cofigs/.google_service_config.jar`(24,295 B) |
| パッケージ | **`com.android.system.statlib`** |
| エントリクラス | **`STMM`** |
| 実体 | 第3段B(`com.android.systemupdate`)の**難読化リスキン版** |

第3段Bとの差分:

- XOR鍵が別: `[24,17,17,13,27,21,33,18,19,14,15,16,14,18,10,18,18,19,15,15]`
- SharedPreferences のキー名を変更(`cxuwrs72dsj`→`KRKgiriehgkf` 等)
- **第3段Bにない8番目のC2 `https://oulers.c4moosem.com` を追加**
- ビーコン間隔を鈍化(C2要求 24時間間隔 / サービス再起動 7日 ← 第3段Bは約1時間 / 15日)
- クラス名変更: `STMM`=EntryPoint、`OLM`=MainRun、`o`=TaskRun、`p`=HttpClient、`l`=StringSecurity

能力(逆コンパイル済みソースから確認): `getDeviceId` / `getImei` / `getSubscriberId` による識別子収集、`checkServerTrusted` の空実装(TLS検証無効化)、`Runtime.getRuntime` によるコマンド実行。

**つまり第4段は新種の攻撃機能ではなく、C2チャネルの冗長化・長期潜伏化を担うモジュールである。** 端末に対する能力の上限は第3段の時点と変わらない。

利用可能な資料: 逆コンパイル済みソース47クラス2,349行(`V6/raw_unpacked/com.android.system.statlib/`)、注釈付き版(`V6/payload_deobfuscated/google_service_config/`)、V7世代のバイナリ検体(`V7/bins/decrypted_payload.jar`)。

### 運用手法 — CDN 経由の使い捨てサブドメイン

パッシブDNS では `s6jvxl.com` の apex は Porkbun のパーキングIP(`44.227.76.166` 等)にしか解決せず、Wayback Machine の記録も「parked domain」のみ。**apex は一度もコンテンツ配信に使われていない。**

一方 urlscan.io に、**2026年1月19日**の別サブドメインのスキャン記録が2件残っている。

```
http://n2w6h8.s6jvxl.com/          185.111.111.154  AS212238 CDNEXT/Datacamp
http://n2w6h8.s6jvxl.com/updates/   37.19.207.37    AS60068  CDN77/Datacamp
PTR: *.bunnyinfra.net   Server: BunnyCDN-DE1-1328   証明書: Let's Encrypt E7 (2026-01-14発行)
```

**運用者は bunny.net の CDN プルゾーンの背後に C2 を隠し、ランダム6文字のサブドメインを短期間で使い捨てている**(`w5ybj0`, `n2w6h8`, `z59ux9`, `afpik8`, `l2hz2z`, `s4gcb9`, `c2b3db`, `oulers`)。apex のパーキングは偽装である。`n2w6h8` は**2026年1月時点で稼働中**だった。

## 6. 端末と関係企業

### 端末: SOYES XS19 Pro

3.8インチ小型スマートフォン、MediaTek MT6762(Helio P22)、Android 12。AliExpress / Alibaba / Sunsky で販売。ブランド元は深圳市搜野科技(SOYES)。

**Amazon US では「Truely」ブランドでリバッジ販売されている**(型番は XS19 Pro のまま)。同一ファームウェアが複数ブランドで流通している可能性が高い。

SOYES 系には前科がある。Pen Test Partners は SOYES S7 に Domino 系バイナリ(`smsdamon` / `smsservice` — C2通信とサイレントインストール)、姉妹機 ZOKOE XS13 に IMEI 書き換えアプリを発見している。XDA には「remove backdoor in Soyes mini smartphone」というスレッドが存在する。

**ただし XS19Pro 固有のマルウェア報告は存在しない。本調査が初出とみられる。**

### 「YRCT」/ szyrct.cn — 公開情報ゼロ

企業登記・検索エンジン・ICP登録のいずれにも該当なし。`szyrct.cn` は Tencent Cloud 経由で**個人名義**、ICP届出なし、Aレコードなし。実体不明のホワイトラベル表記と見るべきである。

### `otauc.com` / `com.otauc.aiot.tbx.fota` — 完全に未記録

ドメインは2014-08-20登録(Alibaba Cloud、四川省)。`api.otauc.com` → `47.88.189.18`、`www.otauc.com` → `115.29.160.142` は解決するが応答しない。**11年間 Wayback Machine に一度もアーカイブされていない。**パッケージ名は公開インターネット上のどこにも存在しない。本端末で最も不透明な構成要素である。

### Redstone OTA — 正規ベンダだが前歴あり

`ro.redstone.appid` の Redstone(北京红石阳光科技 / redstoneota.com)は MediaTek 公認の FOTA プラットフォーム。そのクライアント `com.redstone.ota.ui` は:

- Malwarebytes が `Android/PUP.Riskware.Autoins.Redstone` として検出、**2021年 Gigaset 事件の配信経路**
- Dr.Web が `Android.DownLoader.3894` として検出
- Falcon Sandbox が **98/100 の悪性度**判定(DexClassLoader 注入、`Runtime.exec()`、`/cache/recovery/command` 書き込み)

### heils.cn — 実在企業

深圳禾思众成科技有限公司(ICP 粤ICP备17094398号)。`face.heils.cn` / `license.heils.cn` は `47.106.37.233`(Alibaba Cloud 深圳)。**マルウェア報告はない。**

ただし同社の公開製品は産業用マシンビジョンであり消費者向け顔認証ではない。また `cn.heils.faceunlock` は APK 集約サイト・サンドボックスのいずれにも記録がない。Google の2019年 Triada 開示が、**顔認証機能の外注をサプライチェーン侵入の入口として名指ししている**点は留意に値する。

## 8. 推奨する次の行動

1. **公開リポジトリの保全** — 本件唯一の公開解析であり、消失リスクがある。恒久的な場所への複製を推奨する。
2. **7つの追加C2ドメインの照合** — 特に `cfiles.f4dc6d8n.com`(ペイロード配信)と `c2b3db.s8pa9zb2.com` / `s2f3c4ab.com`(最も新しい稼働先)を、ネットワークログ・DNSログに対して検索する。
3. **登録一括性を起点とした横展開** — NameCheap で 2025-06-19 06:54:31 に登録され、Cloudflare NS `sri`/`suzanne` を使うドメイン群から未知の兄弟ドメインを列挙できる。
4. **ベンダへの通報** — Dr.Web と Kaspersky は本クラスタ(Triada.231 / Keenadu)を追跡中だが、本件の指標を保有していない。Google にも SOYES XS19 Pro / Truely XS19 Pro として報告する価値がある。
5. **2系統のサイレントインストール経路(Redstone / otauc)とインプラントの関係** — 共犯なのか単なる同居なのかは未解決であり、別途の調査対象となる。

## 9. 判断の根拠区分

**本調査で自ら検証した事項:**
- 公開検体とのバイト単位一致(`cmp` による直接比較)
- C2 URL の一致
- 注入ネイティブ関数7種の自検体における存在
- C2ドメイン一覧の抽出

**公開情報に基づく事項(出典明記済み):**
- ファミリー判定(Dr.Web / McAfee / Kaspersky / Trend Micro / HUMAN の各報告)
- 第4段の内容(第三者の逆コンパイル結果。自らバイナリを取得したものではない)
- ドメイン登録情報・パッシブDNS・urlscan 記録
- 端末・企業の同定

**未解決の事項:**
- 本端末で実際にどのデータが送信されたか(C2応答の実測はできていない)
- Redstone / otauc とインプラントの関係
- `M9FNY5PNCx2ZwJam` が実際にドメインリスト復号鍵であるかの検証(SharedPreferences に到達できないため未確認)
